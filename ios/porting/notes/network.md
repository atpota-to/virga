## API for the code that builds on it

All in VirgaNetwork (import VirgaNetwork; depends only on VirgaCore). Paths under ios/VirgaKit/Sources/VirgaNetwork/. Every network function takes `transport: any HTTPTransport = HTTP.transport` (and `clock: NetworkClock = HTTP.clock` where it waits/reads time). Cancelling the Swift task = the web's AbortSignal.

HTTP (HTTP/)
- struct HTTPHeaders (Fetch Headers: case-insensitive, values trimmed; ExpressibleByDictionaryLiteral; get/has/set/append/delete; `canonical: [String:String]` lower-cased).
- struct HTTPRequest(method: "GET", url: String /*exact string the web built*/, headers:, body: Data?, timeoutMs: Double? /*AbortSignal.timeout*/); also init(method:url:headers:text:timeoutMs:).
- struct HTTPResponse(status, statusText "", headers, body: Data, url); `ok`, `json() throws -> JSONValue` (= res.json(): UTF-8, BOM dropped; a body that isn't JSON throws JSONSyntaxError with V8's message), `jsonOrNull()`, `text()`, static `.json(_:status:headers:)`.
- struct JSONSyntaxError: Error { message; name "SyntaxError"; static v8(_ text: String) -> JSONSyntaxError? } — JSON.parse's SyntaxError in V8's words (held to Node by fixture network.jsonSyntax). Use it wherever a port shows a JSON.parse failure's message.
- protocol HTTPTransport: Sendable { func send(_ request: HTTPRequest) async throws -> HTTPResponse } — throws HTTPTransportError {.timedOut ("The operation was aborted due to timeout"), .network(String) /*"fetch failed"*/, .invalidURL} or CancellationError.
- URLSessionTransport(session: .shared): Linux-safe (FoundationNetworking), sends nothing once the task is cancelled, whole-exchange deadline from request.timeoutMs, URL parsed with WebURL.
- final class MockTransport (public, for tests AND VirgaDemo): `on(_ matcher, times: Int? = nil, respond: Response)`, `on(_ method: String, _ matcher, times:, respond:)`, closure variants `respond: @Sendable (HTTPRequest) async throws -> Response`. Matcher: .url(exact, by code unit), .urlPrefix, .path("/xrpc/<nsid>") (any host/query), .regex (over JSRegexSubject), .predicate(name, fn), .any. Response: .json(JSONValue, status:, headers:), .text(_, status:, contentType:), .bytes(Data, status:, contentType:), .status(Int), .response(HTTPResponse), .networkError(msg), .timeout, .hang. Routes tried in order; `times:` routes step aside when used up. `requests`, `unexpected`, `remainingRoutes`, `clearRequests()`. Unmatched request throws MockTransportError.unexpectedRequest listing routes. (A responder can cancel the calling task with `withUnsafeCurrentTask { $0?.cancel() }` to stand in for an abort mid-request.)
- struct NetworkClock(now: () -> Double epoch ms, sleep: (ms) async -> Void /*returns early on cancel*/); `.live`, `.instant(now:)`.
- enum HTTP { static var transport; static var clock } — the app's defaults (web's global fetch/setTimeout); demo/UI tests may set a MockTransport.
- func withDeadline<T>(ms: Double?, _ op) async throws -> T (throws .timedOut).
- func jsMessage(_ error) -> String: err.message for any error.

XRPC (XRPC/)
- struct XRPCAgent(did: String?, fetchHandler: any XRPCFetchHandler); init(service: String, transport:) (= new Agent(serviceUrl)). Sends atproto-accept-labelers "did:plc:ar7c4by46qjdydhdevvrndac;redact" + configured labelers on every call, atproto-proxy after withProxy. Methods: `query(nsid, XRPCParams?, options:) -> XRPCResponse`, `procedure(nsid, input: Input?, params:, options:)`, typed `query(_:_:as: T.Type)`, `procedure(_:input:params:as:)`, generic `call(nsid, kind: .query/.procedure, params:, input:, options:)`, `withProxy(serviceType, did)` (no DID validation), `withBlueskyAppView()` (= withProxy(...APPVIEW_SERVICE)), `configureLabelers`, `configureProxy`, `setHeader`. Input: .json(JSONValue) | .bytes(Data) | .text(String) | `.encoding(Encodable)`. CallOptions(headers: [(String,String)], encoding: String? /*"" = none*/, hasSignal: Bool). Throws XRPCError for every failure (CancellationError passes through). A JSON answer that isn't JSON is XRPCError(2, "InvalidResponse", "Failed to parse response body: SyntaxError: <V8 message>"); one with a `__proto__` member anywhere is XRPCError(2, "InvalidResponse", "Failed to parse response body: TypeError: Invalid key: __proto__"), as the SDK.
- XRPCResponse { body: .json/.text/.bytes; headers [String:String]; `data: JSONValue`; `bytes`; `decode(T.self)` }.
- struct XRPCError: Error { status: Int (ResponseType code; 1 = no response), error: String (lexicon name or ResponseType name), message, headers: [String:String]? }; `XRPCError.from(error)`; `json`. enum XRPCResponseType (from(httpStatus:), name, words).
- XRPCParams: ordered, ExpressibleByDictionaryLiteral of (String, XRPCParamValue?); nil = omitted; subscript by name (code unit). XRPCParamValue: .string, .integer (sent as Int32 like `|0`), .float, .boolean, .datetime, .array (repeated keys), `.strings([String])`. XRPCPath.methodCallURL(nsid, params).
- protocol XRPCFetchHandler { func handle(_ request: XRPCHandlerRequest) async throws -> HTTPResponse } — XRPCHandlerRequest(path "/xrpc/<nsid>?<q>", method, headers, body, hasSignal). ServiceFetchHandler(service:headers:transport:timeoutMs:).
- enum Pagination: `collect(startingAt:, maxPages:, stopOnEmptyPage: true, repeatedCursor: .follow|.stopOnPrevious|.stopOnAny, onPage:, fetch: (cursor) async throws -> Page<Item>) -> Outcome<Item>{items, pages, stop: .complete|.pageLimit|.repeatedCursor|.cancelled, cursor, complete}` — cursors compared by code unit; set the options to match each web loop. Also XRPCAgent.collect(nsid, params, itemsKey:, maxPages:, stopOnEmptyPage:, repeatedCursor:).

Support (Support/) — reuse, don't redefine
- struct DataURL(_ address:): a `data:` address read as the Fetch standard's data: URL processor reads it. `essence` is the lower-case MIME essence (text/plain when there is none or it doesn't parse), `body` the bytes, `picture` the body or nil when it is empty or the type is image/svg+xml; `isDataURL(_:)` checks the scheme only. ## Known gaps and deliberate differences

- Two WHATWG URL parsers in the package: VirgaNetwork's WebURL (approximate UTS #46, no Bidi rule; 391/3,600 random non-ASCII hosts differ from Node) and VirgaPosting's WHATWGURL (matches Node on all of them). The merge should move WHATWGURL down (VirgaNetwork or VirgaCore) and make WebURL a thin wrapper or remove it.
- WebURL (like WHATWGURL) follows the URL Standard where Node 22's ada 2.9 doesn't: relative references on an opaque-path base, '..' in non-special and file paths.
- XRPC: the SDK's lexicon output check (XRPCInvalidResponseError, status 2) and 'Invalid query parameter' refusal aren't ported; a `.json(.array)` procedure input is sent as JSON where the SDK treats an array as an iterable stream; duplicate CallOptions header names overwrite where the SDK throws 'Duplicate header'; withProxy/configureLabelers don't validate DIDs (every web caller passes the constant AppView DID).
- Cancellation is Swift's CancellationError where the web's abort is an AbortError (inside the Agent, an Unknown XRPCError 'This operation was aborted'); BlobUploadError.cancelled and startBackendSignIn's CANCELLED keep the web's names and messages.
- resolveProfiles and uploadBlob convert non-string fields to String / truncate a fractional size (noted in the module map).
- checkActivity returns results in DID order and getPosts' `error` is the last failing chunk in chunk order; the web's follow completion order (nondeterministic).
- HTTPResponse.statusText is '' from URLSessionTransport, so atproto.js's 'HTTP <status> <statusText> for ...' reads as over HTTP/2. Network-failure messages are Node's ('fetch failed'), not a browser's.
- unwrapEnvelope's ratelimit headers: names differing only by case are set, not combined, and an invalid header name or value doesn't throw as the web's Response constructor would.
- VirgaCore's JSONParseError messages are still that port's own; VirgaNetwork's JSONSyntaxError.v8(text) gives V8's and could be adopted there.
- JSSort matches V8 exactly below 64 elements; at 64+ only for consistent comparators.
- sources.js: only publicXrpc/getPosts/resolveHandle/chunk/GET_POSTS_MAX are ported (PublicAppView.swift); library.json still lists sources.js as pending for the library agent.
- Web bugs to report (not fixed): src/lib/atproto.js resolvePds falls back to the first service of any type and matches only the short '#atproto_pds' id, unlike src/session/pds.js; src/lib/activity.js lastActive has no timeout, and its gone regex misses 'AccountTakedown' ('takendown'); src/posting/lib/asyncPool.js keeps starting new items after the first rejection; src/lib/constellation.js backlinkRows returns a non-array records value that callers spread; src/lib/atproto.js getPlcHistory puts the DID into the URL unencoded; src/session/backendClient.js unwrapEnvelope throws a TypeError ('Response constructor: Invalid response status code 304') for an upstream 304 instead of an XRPC error, and would throw for a ratelimit header name or value the Headers constructor refuses.

## What the audit found and fixed

- medium (fixed) src/lib/atproto.js, src/session/backendClient.js, src/lib/activity.js, src/session/pds.js: The interrupted pass (WIP 3cc93d1) was reviewed against the web and kept: strings from outside the app (DIDs, endpoints, paths, header values, cursors, cache keys) compared and tested by UTF-16 code unit; resolveProfiles keeps the web object's key order and code-unit keys (ResolvedProfiles); every request records and replays the deadline the web attaches (request.timeoutMs in _fetch.js); a falsy timeoutMs is no deadline (withDeadline); feedItemTime takes a time zone; ratelimit as a string; empty encoding means none. Three places it left wrong failed swift test and are fixed below.
- medium (fixed) src/session/backendClient.js readBackendReturn: readBackendReturn compared the returned nonce with the pending one through JSONValue ==, which is canonical equivalence, so a nonce that only normalizes to the pending one was accepted (the web's `pending.nonce !== nonce` is code-unit exact). Now compared by code unit; fixture case nonce-code-units.
- medium (fixed) src/session/pds.js pdsFromDidDocument: PDS.pdsFromDidDocument trimmed trailing slashes with Character-based hasSuffix/removeLast (a regression in the WIP), so a '/' after a prepended sign such as U+0600 was not trimmed. Now `/\/+$/` by code unit.
- medium (fixed) src/lib/atproto.js fetchJson, src/posting/library/sources.js publicXrpc, @atproto/xrpc httpResponseBodyParse: Response bodies that aren't JSON failed with this port's own parse messages; the web shows V8's (`Unexpected token '<', "<!DOCTYPE "... is not valid JSON`, `Unexpected end of JSON input`, `Expected property name or '}' in JSON at position 1 (line 1 column 2)`, ...) through res.json() in atproto.js/sources.js and the SDK's "Failed to parse response body: SyntaxError: ...". New JSONSyntaxError rebuilds V8's message (token/place, position, line/column, quoted context); HTTPResponse.json() and XRPCAgent use it. New fixture network.jsonSyntax (798 texts) and 18,000 further random texts matched Node.
- low (fixed) src/posting/library/sources.js getPosts: getPosts deduplicated URIs with Set<String> (canonical equivalence) although its comment said code units; two spellings of 'é' collapsed into one request. Now Set<JSKey>.
- low (fixed) src/session/backendClient.js unwrapEnvelope: BackendFetchHandler answered an upstream 304 as an XRPC 304; the web's unwrapEnvelope calls `new Response(body, { status: 304 })`, which throws TypeError "Response constructor: Invalid response status code 304" (an Unknown XRPC error). Ported with Node's words, plus the RangeError for a status outside 200-599; fixture cases status-not-modified and status-no-content (a 204 reads as 502).
- low (fixed) @atproto/lexicon jsonStringToLex via XrpcClient.call: The SDK's jsonStringToLex refuses any JSON answer containing a `__proto__` member (InvalidResponse, "Failed to parse response body: TypeError: Invalid key: __proto__"), success or failure; the port passed it through. Ported (iterative walk); fixture cases proto-key and proto-key-error.
- low (fixed) src/lib/atproto.js fetchWithTimeout/withTimeout: Atproto.fetchWithTimeout replaced a deadline the request already carried; the web combines a caller's signal with its own timeout (AbortSignal.any), so the sooner wins. Now min(existing, ms); fixture cases own-ceiling, caller-sooner, caller-later.
- low (fixed) src/session/backendClient.js startBackendSignIn, createBackendRequester: startBackendSignIn (and URLSessionTransport) sent the request even when the task was already cancelled; a fetch with an aborted signal sends nothing. Both now check first. Behaviour tests ported from backendClient.test.js: a sign-in called off before, during or after the request goes nowhere (CANCELLED AbortError, nothing assigned or stored); the requester reports TIMEOUT vs NETWORK_ERROR (status 0) and lets the caller's cancellation through.
- low (fixed) src/session/backendClient.js createBackendFetchHandler: Smaller mismatches: an empty method through the proxy is now GET (`(init.method || 'GET')`); XRPCParams' name lookup compares by code unit.
- low (fixed) ios/parity/cases/network.*.js: Fixture coverage was thin in places.
